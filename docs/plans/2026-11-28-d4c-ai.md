# D4c AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The third D4 slice: an owner adds an AI provider from a preset or a custom entry, tests it, lists its models, and picks a default; anyone at `edit` drafts variants for several targets from the composer's AI panel or in random mode, edits them, and publishes; the owner reads the generation history and chooses whether prompts are kept.

**Architecture:** One small backend change (`PATCH /posts/{id}` accepts `generation_id`, so a draft saved before generating still links to its generation). Then web screens over the D2 routes: an AI providers area (owner view and the read-only delegate view, from the `view` discriminator the API already sends), a generation history table, and an AI panel that plugs into the D4b composer through its `applyDraft` action. One error mapping (`ai:failure.<reason>`) serves the test button, the model list, and generation.

**Tech Stack:** Rust (axum, sqlx), React 19, React Router 8, TanStack Query 5, `openapi-fetch`, i18next, Radix/shadcn, Tailwind 4, Vitest + MSW, Playwright.

**Spec:** `docs/specs/2026-11-27-d4-web-publishing-ui-design.md` (sections "Shared decisions" and "Slice details: D4c AI"). Also read plan 03 Phase D2 and Phase D4 and the AI rows of the REST surface in `docs/contracts/03. publishing roadmap.md`, the D2 plan `docs/plans/2026-11-06-d2-drafter.md` and `docs/plans/2026-11-22-d2-model-listing-kinds.md` (presets, model kinds, failure reasons), and the as-built D4b plan `docs/plans/2026-11-28-d4b-compose-publish.md` (the composer's `ComposerState`, `ComposerAction`, `useComposer`). **D4b must be merged before Task 4** (Task 4 uses D4b's `createdByLabel`; Tasks 5 to 7 build on the composer). Tasks 1 to 3 need nothing from D4b. **Before Task 4, check the D4b names this plan consumes against the merged code** (`web/src/features/compose/state.ts`, `ComposerProvider.tsx`, `features/queue/createdBy.ts`); where D4b's "As built" note in the roadmap renamed one, use the built name.

## Review Focus

1. **A provider that fails in a new way:** a key rejected, a model gone, a rate limit with `Retry-After`, a timeout, a local server not running, or output the drafter could not repair. Each `ai_provider_failed` reason shows its own plain sentence and next step, a `Retry-After` shows the wait, and the composer keeps the user's text untouched. Tests in Task 2 (`every failure reason has a sentence`) and Task 5 (`a failed generation leaves the draft as it was`).
2. **Generating over work in progress:** the user has typed text or overrides, then generates. The result replaces only the targets that were sent and only after the user agrees when something would be overwritten; a target left unchecked keeps its text even when it used the shared post (the draft's shared text is the first sent target's). Undo restores the state before the generation, and never brings back a state older than a conflict reload. Tests in Task 5.
3. **A generation whose variants still break rules:** `violations` per account and repair `notes` show in `ViolationList` with their fixes; the draft is still filled so the user can fix it by hand. Test in Task 5.
4. **The key form:** a pasted key with spaces or a newline is trimmed; a custom opencode entry that is not JSON is caught in the browser; one that uses `{env:…}` or `{file:…}`, or breaks another rule, shows each of the server's `validation_failed` `violations` at its path (`field` is set only when neither or both of `preset` and `opencode` are sent); the key field is masked and never prefilled. Tests in Task 3.
5. **A delegate in the AI screens:** an `edit` delegate sees provider names and models, can generate, and sees no add, test, delete, key, or history; a `view` delegate sees no AI panel and no AI providers item; `ai_provider_required` tells a delegate to ask the owner rather than linking to a page they cannot open. Tests in Tasks 4 and 5.

## Decisions taken in this plan

- **Linking a generation to a saved post (call, small backend change):** `PatchPostRequest` gains `generation_id`, linked in the same transaction as the patch. Without it a draft saved before generating would never link to its generation. `POST /posts` links through `AiGenerationRepo::link_unlinked` (only while the generation's `post_id IS NULL`), so the patch cannot reuse it as is: a composer that saves twice after one generation would get `404` on the second save. The patch links through a repository call that also accepts a generation already linked to **this** post (`post_id IS NULL OR post_id = $post`, a no-op answer of success); a generation the owner does not have, or one linked to another post, answers `404` exactly as create does. The client also sends `generation_id` only when it differs from the last saved one (Task 5), so the idempotent answer is a safety net, not the normal path.
- **Language (call):** the panel's language defaults to "Automatic", which omits `language`, so the server applies its own order (the account's writing style, the brand profile, then the interface language) per target. Sending the brand profile's language or the user's locale by default would override every account's writing style. The user may pick an explicit language, which then applies to every sent target.
- **Unsent targets keep their text (call):** `AiDraftDto.post.text` is the first sent target's text, and `applyDraft` writes it into the shared post. Before applying, each target that was not sent and has no override of its own gets an override holding the current shared text, tags, and link, so nothing the user did not ask for changes. Pinned targets lose nothing, so they never trigger the replace question; when it is asked anyway, it lists them as "kept as they are". D4b's plan defines this pinning and `applyDraft`'s `sent: string[]`; Task 5 checks they were built and adds them if not.
- **Undo lifecycle (call):** `beforeDraft` is set by `applyDraft`; cleared by any later edit action (`setBase`, `setTargets`, `setOverride`), by `load` (a conflict reload, so Undo never writes an older state over the server's version), and by `undoDraft` itself (which restores it). `saved` and `savedStep` keep it, so "Undo AI draft" still works right after a save; undoing then makes the composer dirty again, as any edit would.
- **Routes (call):** `/ai` (providers; owner and `edit` delegates), `/ai/new` (add from a preset or custom, owner), `/ai/:id` (edit, owner), `/ai/history` (owner). Nav: SETTINGS → "AI providers".
- **Generate replaces after asking (call):** when the panel's targets already have text or a changed override, Generate asks "Replace the text for {n} accounts?" before dispatching `applyDraft`; the composer keeps one undo step (`undoDraft`), shown as "Undo AI draft" until the next edit.
- **Random mode (spec):** a switch in the composer header, "Write it myself" / "Let AI write it". In random mode the editor shows only the prompt, media, and targets; Generate fills the draft and switches back to controlled mode. Both end in the same `ComposerState`. Switching to random mode with unsaved text asks once; after that, random mode's Generate does not ask again. The mode is the `?mode=ai` search parameter on whichever composer route D4b built for a new post and on `/compose/:postId`.
- **Model choice:** the panel lists the chosen provider's models of kind `text` first; `other` models are listed after them under "Probably not for writing posts" and **can still be chosen**, with the warning "This model may not write text; generation may fail." This keeps D2's "flag, never hide" decision (`2026-11-22-d2-model-listing-kinds.md`): `kind` is a guess from the ID, and a wrong guess must not make a real model impossible to pick. A model with `images: false` shows "Ignores images" when media is attached. The panel starts from the provider's configured `models` (from `useAiProviders()`, no extra request) and loads the live list (`useAiModels`) only when the user opens "Show all models", so opening the composer charges no AI bucket.
- **Request limits in the panel:** the panel checks what the server would refuse before sending: a prompt of at most 8,000 characters (a counter), 1 to 20 targets, at most 10 media, only `ready` media, and a `link` that parses as a URL. Generate is disabled with the reason shown; the server's `422` stays the authority.
- **Live provider checks are the maintainer's (spec):** the D2 entries in `2026-11-27-consolidated-verification.md` are triggered by this slice; Task 8 reminds the maintainer and lists them in this slice's verification file as "now checkable from the UI", without doing them.

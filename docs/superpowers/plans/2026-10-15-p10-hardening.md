## Spec amendments decided while planning

1. **Review before plan.** The threat review was performed during planning; this plan holds the concrete fixes. `docs/security.md` is the findings register (threat, control, test, status) and G3 extends the same file.
2. **Fix bar.** Every finding is fixed in P10 unless the fix needs plan 03 code; those are recorded as "deferred to B6/G3", not "accepted". Six low risks are accepted (list in Task 11).
3. **Constant error shape** means: every malformed or invalid bearer yields the same 401 problem+json body (ignoring `request_id`) and `WWW-Authenticate: Bearer error="invalid_token"`, with no reason leaked. Property tests check this at the verifier and at the HTTP layer; 256 cases by default, overridable with `PROPTEST_CASES`.
4. **Client allowlist.** A token is accepted only when its client claim (`auth.oidc.claim_names.client_id`, default `client_id`; fallback `azp`) is in `auth.oidc.allowed_clients`, which defaults to `[auth.oidc.client_id]`. An ID token presented as a bearer stays an accepted risk.
5. **Bearer length cap** of 8 KiB, not configurable; longer is the uniform 401.
6. **`X-Postit-Act-As` is rejected** on every request with 403 `forbidden` until plan 03 B6 implements it. No new error code.
7. **Server-set security headers on the web listener:** `Content-Security-Policy` derived from config (API origin + issuer origin) with one full-string override `server.web.content_security_policy`, plus `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin` and `X-Frame-Options: DENY`. HSTS stays with the TLS terminator. Dev nginx drops its own CSP so one policy applies.
8. **API response headers:** `/api/v1/*` gets `X-Content-Type-Options: nosniff`, `Cache-Control: no-store` (unless the handler set one) and `Referrer-Policy: no-referrer`; `/backend/openapi.json` gets `nosniff`.
9. **Web token handling:** renewal by refresh token only (never the iframe); a reload restores the session with a top-level `signinRedirect({ prompt: 'none' })`, guarded against loops by a `sessionStorage` flag that holds no token; `login_required` and its siblings return to the sign-in screen with no error notice. The OIDC `state`/PKCE store moves from `localStorage` to `sessionStorage`; sign-out revokes the refresh token. CSP becomes `frame-src 'none'; frame-ancestors 'none'` (reverting P7's amendment), and `cargo xtask zitadel-bootstrap` stops enabling Zitadel iframe embedding.
10. **Last-admin guard** takes one transaction-scoped advisory lock (the bootstrap key, renamed `ADMIN_SET_LOCK_KEY`) before reading the target row, in disable, demote, delete and self-delete. Review found the current per-row `FOR UPDATE` ordering can deadlock when two admins act on each other at once.
11. **Leftover deferred items folded in:** P4 ruling #2 (above) and #5 (a reusable no-secret-leak harness). The vacuous cache test from P4 was already rewritten (`identity/tests/cache.rs:63` waits for LISTEN and asserts a targeted eviction); nothing to do.
12. **Supply chain:** the `web` CI job runs `pnpm audit --prod --audit-level high`. No Dependabot.

## Review Focus

- **A reload with no IdP session must not loop.** `prompt=none` returns `login_required`; the app must land on the sign-in screen once, with no notice, and a second reload must not redirect again (Task 9, tests `restores_once_per_tab` and `silent_errors_show_no_notice`).
- **A valid token whose `client_id` is missing but `azp` matches** (other IdPs) must be accepted; one with neither must be refused with the uniform 401 (Task 2, `client_falls_back_to_azp` and `token_without_client_claim_is_refused`).
- **The web app served on the API origin** (no `server.web.bind`) must still get the web security headers on `/`, `/assets/*` and deep links, and the API paths must not get the web CSP (Task 8, `dispatch_keeps_api_and_web_headers_apart`).
- **Two admins disabling each other at the same moment** must end with exactly one success and one `last_admin`, never a 500 from a Postgres deadlock (Task 6, `concurrent_mutual_disable_leaves_one_admin`).
- **An `X-Postit-Act-As` header on an unauthenticated or rate-limited request** must still count against the per-IP bucket and must never be silently ignored (Task 5, `act_as_is_charged_to_the_ip_bucket`).

```rust
//! Malformed tokens through the JWT parsing path: no panic, always an error, and a mutated
//! genuine token is either refused or still carries the genuine claims.
#![cfg(feature = "testkit")]

use std::sync::LazyLock;
use std::time::Duration;

use base64::Engine;
use base64::engine::general_purpose::URL_SAFE_NO_PAD;
use chrono::Utc;
use jsonwebtoken::Algorithm;
use postit_identity::testkit::Keys;
use postit_identity::verifier::Verifier;
use proptest::prelude::*;

const ISSUER: &str = "https://issuer.test";

fn verifier() -> Verifier {
    Verifier::new(
        ISSUER,
        vec!["postit".to_string()],
        vec![Algorithm::RS256, Algorithm::ES256],
        Duration::from_secs(0),
    )
    .require_client("client_id", vec!["postit-app".to_string()])
}

/// One RSA key pair for the whole binary: generating one per case (4 properties x 256
/// cases) takes minutes, and the properties do not depend on which key signs.
static KEYS: LazyLock<Keys> = LazyLock::new(Keys::generate);

fn genuine(keys: &Keys) -> String {
    let now = Utc::now().timestamp();
    keys.mint(
        &serde_json::json!({
            "sub": "s", "iss": ISSUER, "aud": "postit", "exp": now + 3600,
            "client_id": "postit-app",
        }),
        Algorithm::RS256,
    )
}

fn segment() -> impl Strategy<Value = String> {
    prop::collection::vec(any::<u8>(), 0..512).prop_map(|b| URL_SAFE_NO_PAD.encode(b))
}

fn header_json() -> impl Strategy<Value = String> {
    (
        prop::sample::select(vec!["none", "HS256", "RS256", "ES256", "PS256", "", "rs256"]),
        prop::option::of("[ -~]{0,64}"),
        prop::option::of("[ -~]{0,16}"),
    )
        .prop_map(|(alg, kid, typ)| {
            let mut h = serde_json::json!({ "alg": alg });
            if let Some(kid) = kid {
                h["kid"] = kid.into();
            }
            if let Some(typ) = typ {
                h["typ"] = typ.into();
            }
            URL_SAFE_NO_PAD.encode(h.to_string())
        })
}

proptest! {
    #[test]
    fn arbitrary_text_is_refused(token in "[ -~]{0,2048}") {
        prop_assert!(verifier().verify(&token, &KEYS.jwks()).is_err());
    }

    #[test]
    fn three_random_segments_are_refused(h in segment(), p in segment(), s in segment()) {
        let token = format!("{h}.{p}.{s}");
        prop_assert!(verifier().verify(&token, &KEYS.jwks()).is_err());
    }

    #[test]
    fn forged_headers_with_random_signatures_are_refused(h in header_json(), p in segment(), s in segment()) {
        let token = format!("{h}.{p}.{s}");
        prop_assert!(verifier().verify(&token, &KEYS.jwks()).is_err());
    }

    #[test]
    fn a_mutated_genuine_token_is_refused_or_unchanged(index in any::<prop::sample::Index>(), byte in 0x21u8..0x7f) {
        let keys = &*KEYS;
        let token = genuine(keys);
        let mut bytes = token.into_bytes();
        let i = index.index(bytes.len());
        bytes[i] = byte;
        let mutated = String::from_utf8_lossy(&bytes).into_owned();
        if let Ok(claims) = verifier().verify(&mutated, &keys.jwks()) {
            // Changing only base64 padding bits can leave the decoded token identical.
            prop_assert_eq!(claims.sub, "s");
            prop_assert_eq!(claims.iss, ISSUER);
        }
    }
```

```rust
/// Everything the current thread logs while the guard from [`LogCapture::install`] lives.
/// Tests using it should run in their own test binary: tracing's callsite-interest cache
/// is process-wide.
#[derive(Clone, Default)]
pub struct LogCapture(Arc<Mutex<Vec<u8>>>);

impl LogCapture {
    /// Installs a thread-default subscriber at `TRACE` that writes into the capture.
    #[must_use]
    pub fn install() -> (Self, tracing::subscriber::DefaultGuard) {
        let capture = Self::default();
        let subscriber = tracing_subscriber::fmt()
            .with_max_level(tracing::Level::TRACE)
            .with_ansi(false)
            .with_writer(capture.clone())
            .finish();
        (capture.clone(), tracing::subscriber::set_default(subscriber))
    }

    /// What was logged so far.
    #[must_use]
    pub fn text(&self) -> String {
        String::from_utf8_lossy(&self.0.lock().unwrap_or_else(PoisonError::into_inner)).into_owned()
    }
}

    fn write(&mut self, buf: &[u8]) -> std::io::Result<usize> {
        self.0
            .lock()
            .unwrap_or_else(PoisonError::into_inner)
            .extend_from_slice(buf);
        Ok(buf.len())
    }
    fn flush(&mut self) -> std::io::Result<()> {
        Ok(())
    }
}

impl MakeWriter<'_> for LogCapture {
    type Writer = Self;
    fn make_writer(&self) -> Self::Writer {
        self.clone()
    }
}
```

- [ ] **Step 1: Write `docs/security.md`**

Sections, in this order, in plain prose and tables (normal American English):

1. **Scope and method.** Foundation surface as of P10 (2026-10-15); reviewed by reading the code paths named in each row; plan 03 G3 extends this file for publishing, delegation, uploads and outbound requests.
2. **Findings register**, one table per surface with columns *Threat*, *Control*, *Test*, *Status* (`fixed in P10`, `in place`, `accepted`, `deferred to B6/G3`). Rows:
   - *Token validation:* algorithm confusion (HS* never accepted, allowlist; `identity/tests/verifier.rs`; in place); `alg: none` (header decode fails; verifier tests; in place); missing or wrong `aud`/`iss`, expired, not yet valid (`verifier.rs` tests; in place); token for another client in the same IdP project (`require_client`; `token_from_another_client_is_refused`; fixed in P10); oversized bearer (8 KiB cap; `an_oversized_bearer_is_the_uniform_invalid_token`; fixed in P10); parser panics or reason leaks (property tests `verifier_props.rs`, `malformed_tokens.rs`; fixed in P10).
   - *Signing keys:* unknown-`kid` refetch flood (at most once per 60 s per process, single flight; `identity/tests/discovery.rs`; in place); IdP outage (stale JWKS kept; in place, documented).
   - *Principal cache:* staleness after disable (LISTEN eviction, generation counter, TTL; `identity/tests/cache.rs`; in place, see accepted risks).
   - *Rate limits and client address:* per-IP for unauthenticated and failed tokens, per-user for authenticated, stricter provisioning gate (`api/tests/middleware.rs`; in place); `X-Forwarded-For` honored only from `server.trusted_proxies`, read right to left (`client_ip.rs` tests; in place).
   - *CORS:* origin allowlist, no credentials, fixed header lists (`router.rs`; in place).
   - *Act-as:* header refused until B6 (`act_as_is_forbidden_everywhere_until_delegation_exists`; fixed in P10); delegation resolution, levels, no re-delegation (deferred to B6/G3).
   - *Admin surface and job console:* every `/users`, `/admin/*` operation refuses a member (`every_admin_operation_refuses_a_member`, an OpenAPI-driven sweep; fixed in P10); console shows summaries and error kind/code only (`api/tests/jobs.rs` including `the_console_never_leaks_a_send_email_failure`; in place); last-admin race (advisory lock; `concurrent_mutual_disable_leaves_one_admin`; fixed in P10).
   - *Secrets in output:* shared `assert_no_leak` harness over logs, errors, `Debug` and problem bodies for bearer tokens, SMTP password, database password, pseudonym key (`http`, `api`, `mail`, `server` redaction tests; fixed in P10).
   - *Web app:* tokens in memory only, state/PKCE in `sessionStorage`, refresh-token rotation, revocation on sign-out, no iframes (`userManager.test.ts`, `tokenSource.test.ts`, `SessionProvider.test.tsx`; fixed in P10); CSP and headers from the server (`backend/tests/web.rs`; fixed in P10); API responses `no-store`/`nosniff` (`api/tests/hardening.rs`; fixed in P10).
   - *Dependencies:* `cargo deny` (Rust advisories, licenses) and `pnpm audit --prod --audit-level high` in CI (in place / fixed in P10).
3. **Accepted risks**, each with its reason and the condition that would reopen it:
   1. CORS preflights and the static web listener are not rate-limited (cheap, no state, no data).
   2. An ID token presented as a bearer is accepted (same user, same client, short-lived).
   3. A disabled user keeps access on other processes for up to `auth.principal_cache_ttl` (default 5 minutes; LISTEN eviction usually makes it immediate).
   4. During an IdP outage, issued tokens stay valid until they expire.
   5. The unknown-`kid` refetch limit is per process: N API replicas can make N fetches per minute.
   6. Each page reload costs one visible redirect to the IdP to restore the session.
   7. Only if Task 1 found that Zitadel does not rotate refresh tokens: a stolen refresh token stays usable until it expires or the user signs out (it lives in memory only and is revoked on sign-out).
4. **Reporting.** How to report a vulnerability (GitHub private advisory on `asm2025/postit`).
